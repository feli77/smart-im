# MVP 验证记录（v0.2 Rime 重构）

验证日期：2026-09-30。环境：Linux x86_64，Python 3.12.3、Lua 5.4（Lupa 2.8）；自带 NumPy 小模型。Windows 小狼毫真机、实际 Rime 部署与真实 GGUF 权重尚未验证。

## 自动化覆盖

- Rime 排序：仅返回外部候选索引；保留重复词与原对象；模型上下文增益；异常整批回退；Rime 路线不加载旧解码器。
- 信箱服务：协议大小与排列校验、旧请求淘汰、会话隔离、单实例、学习事件去重、临时文件过期与退出清理。
- Lua：在真实 Lua 5.4 中执行插件，以模拟的 Rime 对象验证 Tab、候选范围、元数据、版本、模式切换和学习事件；并非实际 librime 会话。
- 跨模块：10 项真实 Lua → 文件 → Python Engine → 文件 → Lua 整合测试，包含双重学习开关、模型失败提示、服务关闭与候选长期停留后的重试。
- 安装：原有配置保留、冲突预检、强制更新备份、重复安装和 CLI。
- 拼音：全拼、简拼、音节分隔、声调与 ü、组合词、单步拼写容错、输入长度和非法字符。
- 排序和学习：真实模型的同音上下文区别、词表外词的分词证据、重复选择改序、新词和多音字持久化、私人表达预测。
- 隐私：学习默认关闭，private 请求不访问个人词库；仅提交时写入；短上下文上限；删除与数据库权限。
- 模型：真实权重载入、离线运行、评分及预测、训练重现；可选 GGUF 的路径/缺依赖/模拟后端接口与 token 预算。
- Qt：真实后台引擎，拼音选词、快速连打空格、Emoji 后选区替换、光标移动取消组合输入、长文纠错偏移、窗口生命周期。
- Windows：结构体 ABI 与 Unicode 代理对、注入过滤、按键按下/释放配对、模式关闭直通、焦点变化、同窗口鼠标变化取消过期提交。使用模拟 Win32 API，不能替代真机上屏验证。

执行：`QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q`，最终结果 **266 passed in 6.56s**。测试文件自行配置 offscreen；开发依赖中包含 Lupa。

Ruff 检查与格式校验通过。v0.2 wheel 和源码包构建成功。在独立环境安装 wheel，确认无需 PySide6 即可安装两个 Rime 资源并执行排序；`rerank 实时 事实 实施 --context 我们计划` 返回 `[2, 0, 1]`；旧版 `suggest nihao` 首选仍为“你好”。第三方 `luna_pinyin` 词典不随包分发。

实际启动 `python -m smart_im serve` 子进程：等待心跳后写请求，读取正确结果，再发送 Ctrl+C。进程以 0 退出，信箱只留下单实例锁文件；默认模式没有生成学习数据库。该次请求从写入到收到结果为 **16.05 ms**，仅作为功能冒烟记录，不是延迟基准或 Windows 指标。

## 历史延迟测量（v0.1 独立引擎）

以下数据来自重构前的独立演示引擎，不覆盖本版 Rime、Lua、文件信箱和 Tab 交互链路。

完整数据见 [benchmark.json](benchmark.json)，复现命令：

```sh
python scripts/benchmark.py --output docs/benchmark.json
```

| 项目 | 样本数 | p50 | p95 | 最大值 |
|---|---:|---:|---:|---:|
| 首轮组合查询 | 100 | 0.241 ms | 0.870 ms | 1.549 ms |
| 重复组合查询 | 1,000 | 0.243 ms | 0.766 ms | 6.901 ms |
| 上下文短语预测 | 100 | 0.012 ms | 0.241 ms | 1.569 ms |

引擎初始化 30.930 ms，不含 Python 进程启动和模块导入。基准采用脚本中固定的 10 种拼音和 10 种上下文，学习关闭；重复查询可能命中缓存。预测样本包含无建议的上下文。数值只说明该有限测试负载的引擎开销，不代表中文准确率、最坏延迟或真实 Windows 端到端延迟。

桌面输入使用 25 ms 防抖和后台推理，故界面完整响应时间还应计入防抖、线程调度、布局与上屏。可选 GGUF 不在这些数字内。
