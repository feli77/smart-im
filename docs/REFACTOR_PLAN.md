# Rime 最小重构计划

## 本版交付边界

目标：在小狼毫/Rime 原有候选上进行本地 AI 重排，确认上屏后可选学习，AI 不可用时正常中文输入仍可用。

流程：输入拼音 → Rime 显示基础候选并提交后台请求 → Tab 应用已完成的 AI 排序 → 空格/数字正常选词。Tab 时结果尚未完成就保持原候选，提示稍后再按。首版不自动刷新或突然重排正在选择的候选。

保留现有模型、学习、纠错、桌面体验台与旧浮窗作为演示/回归基线。主使用路线改为小狼毫 + 独立 Smart IM 方案 + 本地服务。

## 最小架构

- 小狼毫提供 TSF、候选 UI、上屏；不 fork 或修改其源码。
- Rime 使用现有 `luna_pinyin` 词典/简体配置提供拼音候选。
- 一个 Lua 模块提供 processor/filter，保留原始 Candidate 对象，仅重排有限数量且范围一致的候选。
- Python 接收候选文本和当前会话提交的有限上下文，返回原候选索引排列。模型不生成替代拼音候选。
- Lua 标准库文件 I/O + Python 标准库实现异步本地文件信箱。无 HTTP 服务、无额外 Lua 网络扩展、无每键启动进程、无同步等待模型。
- 专用方案关闭 Rime 用户词典学习；首版个人词频与上下文只由现有 SQLite 保存，避免重复学习。默认关闭 AI 学习；服务 `--learn` 与方案学习开关须同时开启才读写统计。
- 运行时信箱只存有限的当前请求、结果和待处理确认事件，并清理过期文件；它不是加密通道，退出异常时可能有短期残留。个人库与信箱分开管理。

## 实现顺序

1. 抽出外部候选排序 API，保证旧演示路径回归通过。
2. 实现有界消息协议、后台服务、过期/异常回退和学习事件去重。
3. 实现 Lua filter/processor 与专用 schema，提供安装命令，只写本项目命名文件，不改用户现有方案。
4. Python 单元测试、真实 Lua 运行时测试、Lua ↔ Python 信箱整合测试、构建与文档。

不扩展：自动异步候选刷新、真实应用正文、文内灰字、空输入续写、C++ 插件、安装器、云服务、Personal LM 训练。保留已存在的演示预测接口，不把它冒充本版 Rime 功能。

## 验收

- 外部候选可随上下文改变顺序；输出只能是输入候选的排列，重复文本和原始 Candidate 元数据不丢失。
- 无服务、超时、错误结果、过期输入、不同候选范围时回退原候选。
- 只有按 Tab 才应用 AI 顺序；普通空格/数字继续沿用当前显示顺序。
- 显式上屏才学习，默认不开启；切换学习状态使旧结果失效。
- 方案可独立安装，原有用户配置不覆盖；Windows 真机端到端验收如无法在当前 Linux 环境执行需明确标注。

## 实施状态

上述四步已完成：外部候选接口、后台服务、Lua/schema、安装命令及文档均已落地；266 项测试、Ruff、构建和独立 wheel 安装验证通过。Windows 小狼毫真机验收仍待执行，具体记录见 [验证说明](VALIDATION.md)。
