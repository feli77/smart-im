# 模型后端与能力边界

Smart IM 只调整 Rime 已有候选的顺序，不生成新的候选或替换输入法词典。提供随包运行的 `tiny` 演示后端，以及通过本机 Ollama 调用预训练 Qwen 的 `ollama` 后端。更换后端不需要自行训练模型。

## Qwen / Ollama 后端

先安装 [Ollama](https://ollama.com/download/windows)，下载选定模型，再启动 Smart IM 服务。例如：

```powershell
ollama pull qwen3:1.7b
.\.venv\Scripts\python.exe -m smart_im serve --backend ollama --model qwen3:1.7b
```

`ollama` 后端未指定 `--model` 时使用 `qwen3:1.7b`，CLI 与 PowerShell 启动脚本保持一致。模型首次下载需要网络，后续通过本机 API 推理。Python 项目不依赖 PyTorch 或 Ollama Python SDK。

截至 2026-09-30，Ollama 官方库提供以下 Q4_K_M 量化版本：

| 模型 | 官方下载体积 | 选择建议 |
|---|---|---|
| [qwen2.5:0.5b](https://ollama.com/library/qwen2.5:0.5b) | 398 MB | 更小的兼容选项；本轮未下载或验证排序质量 |
| [qwen3:0.6b](https://ollama.com/library/qwen3:0.6b) | 523 MB | 可显式选择；旧整组排序质量差，新策略改善但仍有误判 |
| [qwen3:1.7b](https://ollama.com/library/qwen3:1.7b) | 1.4 GB | 默认值；RTX 5060 Laptop 8 GB 上已实测首选提升策略 |

下载体积不是运行内存需求；实际占用还包括推理运行时和上下文缓存。本轮 `ollama ps` 确认 0.6B 和 1.7B 均为 `100% GPU`；真实模型小样本比较见 [验证记录](VALIDATION.md)，不能据此保证一般输入的准确率或每次响应时间。

### 重排方式

每次将完整上下文（最多 128 字）及带索引的候选交给模型，候选拼接最近 16 字上下文形成可直接比较的短语。通过 [Ollama Chat API](https://docs.ollama.com/api/chat) 的结构化 JSON 输出取得 `{"best": index}`，只将最佳项提升到首位，其余保持 Rime 原序。关闭思考，最多生成 32 token；普通请求使用 4096 上下文窗口，大候选池按请求 UTF-8 字节的保守预算扩大窗口，避免静默截断。此方式是提示驱动的候选选择，**不是候选 token 的 logprob 计算，也不对 Qwen 进行训练或微调**。

模型返回值必须是候选范围内的整数索引，布尔值、浮点数、越界、额外字段和未完成输出会被拒绝。客户端据此构造原候选索引的完整排列，即使候选文本重复也保留各自索引。无效输出和推理失败均不能产生新候选，失败时回退 Rime 原序；[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)只能约束格式，不能保证语义判断正确。

没有有效上下文时不请求 Qwen，保留 Rime 原序；若另外启用了个人学习，仍可依据个人统计调整。上下文来自本次 Rime 会话已上屏文本及当前候选前已选的分段，不包含当前应用的完整正文。缺少必要上下文、同音歧义、专业术语和输入者个人意图都可能导致重排错误。重排完成并不要求候选顺序发生变化。

### 本机运行与隐私

服务连接本机回环地址上的 Ollama API，通常为 `http://127.0.0.1:11434`。上下文与候选会传给该本机服务；Smart IM 不因此自动开启个人学习，也不将输入加入模型训练。请使用上述本地模型，并保持 Ollama 的回环监听设置。

Ollama 自身同时提供云功能。如需从 Ollama 配置层禁用云模型和网络搜索，可依照 [Ollama FAQ](https://docs.ollama.com/faq) 设置环境变量 `OLLAMA_NO_CLOUD=1` 后重启 Ollama。关闭云功能不免除首次下载本地权重的网络需求。

## 自带 tiny 演示模型

`src/smart_im/data/tiny_lm.npz` 是实际训练的字符级前馈神经网络：前 4 个字符经过 embedding 和 tanh 隐层，得到下一个字符的概率。运行时以 NumPy 在 CPU 上计算，并将神经概率与语料 n-gram 概率插值。

权重包含 **27,484 个参数、412 项字符词表，约 103 KiB**。训练集为项目自编短句 `src/smart_im/data/corpus.txt`，有效训练字符 2,638 个。训练不使用个人输入。

### 候选评分

`score(context, text)` 返回候选文本的平均字符对数概率，分数越大表示模型认为该文本越可能接在上下文后面。模型只为 Rime 已有候选评分。

排序使用带上下文评分相对空上下文评分的增益，并限制增益幅度，再结合 Rime 原始顺序和可选个人统计。无上下文时不调用模型评分；模型异常或返回非有限数值时保持原始候选顺序。

个人统计来自确认上屏的词频和最多 8 字上下文后缀，存于 SQLite。学习默认关闭，不在线修改模型权重。

### 训练与复现

训练脚本、语料和权重随源码保留。安装项目依赖后可重新训练：

```sh
python scripts/train_tiny_lm.py
```

脚本使用固定随机种子与 Adam，默认输出到 `src/smart_im/data/tiny_lm.npz`。当前分发权重的 SHA256：

```text

```

### 能力边界

模型语料和字符词表都很小，且训练语料中直接包含“我们计划实施新的方案”。这些演示上下文的排序变化不代表通用中文理解能力。词表外字符使用未知字符表示；专业术语、长句和陌生领域的收益没有保证。陌生词仍然会得到有限分数，并不存在因不认识词语而无限等待的逻辑；持续“AI计算中”需要检查服务通信及状态。

## 评测状态

当前有 28 个固定的人工诊断例子及 `scripts/evaluate_ollama.py`，覆盖用户反馈和同音词对照；它不是代表性的独立评测集。脚本调用真实本机模型，单列首个请求，报告后续 p50/p95/最大耗时、首选命中及固定原序基线。普通自动化测试仍使用模拟 HTTP 响应，避免开发测试依赖模型安装。后续评估应使用未参与提示词调整的真实候选数据，分别统计上下文选择、个人学习和两者组合的收益。
